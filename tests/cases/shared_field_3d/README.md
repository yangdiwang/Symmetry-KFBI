# Shared correction field reference and validation

The repository fixtures were generated by actual fixed Python fits from the
reviewed package, independently of C++. They cover U32, rotate, both BVPs, and
include a legal random raw density direction and a harmonic P2 fitted from its
interface Cauchy data. No fixture bypasses fitting by substituting lift coefficients.
The small `package_reference_summary.json` contains the 36 primary package
records selected through their source fields; those numbers are historical
package evidence, not results of a local C++ rerun.

`provenance.json` records the archive SHA256, every consumed source/result hash,
the exporter hash, Python/NumPy/SciPy/pandas/BLAS versions, coordinate conventions,
and hashes for generated files. Python and the source archive are **not** CMake,
CTest, application, or runtime dependencies. Source is never loaded from a
hard-coded temporary review directory. To regenerate into a **new** directory:

```powershell
python scripts/validation/export_shared_field_reference.py `
  --source-dir C:/path/to/reviewed/extraction/KFBI3D_KFBI_SharedField `
  --source-archive C:/path/to/KFBI3D_UPrism_ActualKFBI_SharedField.zip `
  --output output/shared_field_3d/python_reference_new
```

The exporter requires NumPy, SciPy and pandas. It validates all six imported
source files against their reviewed hashes and the archive before import,
disables bytecode writes, and pins numerical environment switches. `--full`
adds complete Z/constraints and transfer observations to runtime output;
`--transforms rotate rotate_translate` adds the second pose. `--run-cases`
also executes the selected N32 PDE cases rather than using saved solutions.

The fixed reference files retain their exact exported bytes through `.gitattributes`.
Do not normalize their line endings: the provenance hashes cover those bytes.

Every `.txt` matrix begins with `rows cols`, then row-major whitespace values.
Integer indices are zero based. Physical vectors are xyz. Full grid IDs are
`(z*(N+1)+y)*(N+1)+x`; Python's interior-only arrays are explicitly mapped into
those IDs. Coefficient/cell lattice indices are lexicographic xyz. C++ first
checks all native labels against the package's analytic labels, and uses native
labels in the actual backend test.

| File | Columns / meaning |
|---|---|
| `surface` | body xyz, outward body normal xyz, area weight, patch ID |
| `volume_samples` | original volume row, body xyz, volume weight |
| `requested_surface` | random requested a, b, harmonic P2 requested a, b |
| `fit_coefficients` | random fitted alpha, random lift, column scale, actually fitted P2 alpha |
| `fit_rhs_samples` | original LS row, q, q-M*lift |
| `probe_points`, `probe_support`, `basis_*` | body points, 64 coefficient IDs, aligned cardinal weights |
| `probe_fit` | random fitted value, actual fitted P2 value |
| `spread_rhs` | full grid ID, Python RHS mapped to the C++ Delta sign convention; omitted entries zero |
| `trace_points` | original trace row, world xyz, outward world normal xyz, weight, patch ID |
| `trace_outputs` | c_value, c_normal, raw_value, raw_normal, fitted_value, fitted_normal, requested_value, requested_normal, equation_value, equation_normal |
| `union_samples` | full grid ID, world xyz, label, shared field value |
| `inside_full_grid_ids` | every interior label, including full-box indexing |
| `cover_starts` | every trace ID and side (-1 interior, +1 exterior), then integer Cartesian start xyz for the full Q27/Q64 tensor cover |
| `observer_rows` | selected trace ID, full Cartesian grid ID, Rg value coefficient, Rg normal coefficient; omitted entries are zero |

The complete cover inventory includes all 1,408 traces and both sides for each
BVP. The C++ test reconstructs every tensor-node ID from the saved integer
starts and requires exact equality (180,224 Q64 and 76,032 Q27 node occurrences).
The exporter also checks the source vectorized starts against its scalar
`Grid.cover3/cover4` methods. Rg rows are a separate 32-trace sample: they merge
both sides and remove box-boundary unknowns, so their sparse support does **not**
describe the complete cover. The C++ test compares every exported coefficient
and checks all additional native sparse entries against zero, with absolute
max-coefficient gates of 2e-14 for value and 5e-13 for normal. These tests do not
use the looser fitted-field response tolerance.

`shared_field_python_fixture_3d_test` consumes these text files using Eigen and
the actual public backend, bulk solver, and half-jump closure. It checks geometry,
sampling, basis derivatives, real fitting, shared transfer, and raw/equation
semantics separately. The fit/response gate uses normalized induced infinity
norm (max absolute entry for vectors), denominator max(1,actual norm,reference
norm), at 1e-8; derivatives are scaled by h or h². Coefficient differences are
diagnostics because the ridge system can amplify factorization differences.

`compare_shared_field_reference.py` also compares fixture trees with hash checks
and per-stage error quantiles. For reduced matrices, provide both Z files. It
checks raw dimensions and orthonormality, compares ZZᵀ, then transports the
candidate matrix to reference coordinates. It never compares unaligned reduced
entries. Near-singular direct variants require `--ill-conditioned-direct` and
report sigma_min and matrix perturbation without the 1% condition-number gate.

For fresh N32 reduced-operator references, use
`scripts/validation/export_shared_field_operators.py` with the same explicit
`--source-dir`, `--source-archive`, and new `--output` arguments. It runs the
reviewed source setup and intercepts its GMRES boundary to evaluate every column
of the actual supplied homogeneous `LinearOperator`. It saves that operator,
the exact source projector's Z, rhs, physical trace/raw-layout metadata, a fresh
random action check, and provenance for all 12 N32 configurations. It stops
before iterative solving and does not reimplement the source forward map.

Use **PowerShell 7 (`pwsh`)** for the runner; Windows PowerShell 5.1 lacks
the .NET `ProcessStartInfo.ArgumentList` API it uses. Run the explicit U32 matrix,
then sequentially expand to all resolutions:

```powershell
./tests/cases/shared_field_3d/run_shared_field.ps1 -BuildDirectory build-3d -Levels 32 -SkipBuild
./tests/cases/shared_field_3d/run_shared_field.ps1 -BuildDirectory build-3d -Levels 32,64,128 -SkipBuild
```

The runner writes only unique `output/shared_field_3d/<run>/` directories. It
always selects backend and target explicitly, isolates inherited experiment
environment settings, saves exact arguments/stdout/stderr/result paths, and runs
one process at a time. It uses the configured Release subdirectory for Visual
Studio builds, falling back to a single-configuration executable path. N32
operator spectra are enabled by default (`-NoSpectrum` disables them); N64/128
never assemble dense operators. It warns at 3.2 GiB and stops its owned solver and the
remaining matrix at 4 GiB by default, preserving the resource failure record.
The measured peak is Windows peak working set; factor estimates and process
memory are different measurements. `-DryRun` validates and records commands.

For this desktop sandbox, the Visual Studio build uses one MSBuild worker with
`/nodeReuse:false` and the x64 preferred tool architecture. Parallel reusable
MSBuild nodes were observed to return exit 1 after a successful target without
compiler diagnostics. Other generators retain two build workers.

The summary separately reports matrix completeness, candidate numerical
acceptance, historical discrepancy investigation lines, and replay verification.
For scopes that do not request `shared_jump`, candidate acceptance is `null`
(not applicable), and successful exit requires every selected control row to
pass; known N32 shared-direct failures still produce a nonzero control-only exit.
The GMRES setting is 2e-10; the independent final true residual certification
bound is 3e-10. Known N32 shared-direct failures remain failed physical research
examples even if a process exits or its equation converges. Missing/NaN/Inf,
resource failures and residual failures remain visible. The runner enables
`--verify-replay` for every case: the executable reloads saved coefficients and
performs one forward, comparing U, the field, and every saved raw/equation trace.
Replay is marked false unless the executable verifies it; merely saving
coefficients is not a verified replay. Convergence orders use only matching
pose/BVP/method series.
