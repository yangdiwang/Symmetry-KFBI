## 2. 算例、离散与自由度

本次对象是**圆环 torus，不是空心直圆柱**：大半径 0.46、小半径 0.18；16 张精确有理双二次 NURBS patch，每张 3×3 控制点。几何没有升成双三次；独立密度空间才是非有理双三次 B 样条。刚体变换为 `Rz(13°) Ry(-11°) Rx(17°)`，无平移。网格为 `[-1,1]^3`，`h=2/N`。

方程为调和制造解的 Laplace 问题。值、梯度和高阶 jump jet 解析计算；Neumann 未知密度为值跳跃，Dirichlet 未知密度为法向导跳跃。二者按 `c=cp+Zy` 进行仿射分解，当前圆环的 `cp=0`。未知密度不通过样本拟合获得。完整公式和代码索引见 [实现说明](TraceFirst_Implementation_20260909.md) 与 [算例配置](../tests/cases/trace_first_3d/results/all32_64_final_20260909/case.json)。

Restrict 为 Neumann Q27-cover3、Dirichlet Q64-cover4；均使用 3+3 法向样本及 extended tubular P2，Spread 使用 P3。GMRES 相对容差 `2e-10`，restart=100，最多 1000 次内迭代。运行器对子进程设置 `OMP_NUM_THREADS=OPENBLAS_NUM_THREADS=MKL_NUM_THREADS=1`；没有采集足以支持跨平台性能归一化的硬件、负载与频率记录。

| N | h | 每 patch 密度分析区间 | Python 原始系数 | 方形 carrier 原始坐标 | carrier C0 坐标 | D 最终 DOF | N 最终 DOF | 外迹点 |
|---:|---:|---|---:|---:|---:|---:|---:|---:|
| 32 | 0.0625 | 4×2 | 560 | 784 | 576 | 240 | 239 | 2048 |
| 64 | 0.03125 | 8×4 | 1232 | 1936 | 1600 | 720 | 719 | 8192 |

carrier 是精确插结嵌入后的表示坐标，不是额外 GMRES 未知量。不能从不同表示阶段的表列中直接相减，声称那就是某一种物理约束消耗的 DOF。对于原始 Python 分析空间，周期 C0/C1 合计减少 320 个（N=32）或 512 个（N=64）独立方向；Neumann 再去掉一个面积均值方向。此次输出没有把 C0 和 C1 的秩分别拆开统计。

外迹点为每个密度单元 4×4 Gauss 点，始终严格多于未知 DOF。D 的点数/DOF 为 8.5333、11.3778；N 分别为 8.5690、11.3936。

| 检查 | N=32 | N=64 |
|---|---:|---:|
| C0 精确嵌入最大差异 | 3.330669e-16 | 2.220446e-16 |
| Neumann 均值零空间残差 | 2.206351e-17 | 1.555830e-17 |
| Gram Cholesky 主元比，N | 0.378776 | 0.324743 |
| Gram Cholesky 主元比，D | 0.379165 | 0.322941 |

主元比仅是分解诊断，不是矩阵完整条件数。这里采用圆环 atlas 的可分离周期 C0/C1，并非通用 C0 特征棱边或 vertex 相容性算法的数值验证。

## 3. 误差与 32→64 观测收敛阶

所有观测阶均按 `p=log(E32/E64)/log(2)` 计算。`interior_l2` 实际是内部网格点上的 RMS：`sqrt(sum(error²)/内部点数)`。`density_l2` 是面积权重归一化 RMS：`sqrt(sum(w*error²)/sum(w))`。它们不是未归一化积分 L2 范数。

密度误差只在本地外迹 Gauss 点上评价：Neumann 与精确值迹比较，Dirichlet 与精确法向导比较。本地未重新生成 Python 的独立非 Gauss 验证点误差、best-approximation 误差或 feature-edge/vertex 分区误差。

## 4. GMRES、完整外迹与未消除的诊断

### 4.1 迭代和真实投影残差

真实投影相对残差在恢复最终 `c=cp+Zy` 与完整已知部分之后重新计算，并非只抄 GMRES 内部估计。

| 问题 | N | GMRES 内迭代数 | 真实投影相对残差 | 收敛标志 | Poisson 调用数 |
|---|---:|---:|---:|---|---:|
| Neumann | 32 | 19 | 1.971345687661e-10 | true | 25 |
| Neumann | 64 | 18 | 1.179824915908e-10 | true | 24 |
| Dirichlet | 32 | 14 | 2.995913517721e-11 | true | 19 |
| Dirichlet | 64 | 13 | 9.128676483756e-11 | true | 18 |

Poisson 调用还包括仿射右端、恢复和额外诊断；Neumann 包含常跳跃探针，不能把 Poisson 次数直接当成 GMRES 次数。

### 4.2 完整未投影外迹

Neumann 主方程控制的是投影后的外部值迹，Dirichlet 控制的是投影后的外部法向迹。下表同时给出两种完整外迹；`active_trace_weighted_l2` 是主外迹的 `sqrt(sum(w*t²))`，**没有除以面积**，不要与第 3 节密度 RMS 混用。

| Neumann | 32 | 7.113922957491e-4 | 3.535010784082e-2 | 2.398127048371e-4 | 约 1 |
| Neumann | 64 | 5.666641475085e-5 | 3.250487351564e-3 | 1.515014623017e-5 | 约 1 |
| Dirichlet | 32 | 3.893165052876e-4 | 1.024909699587e-2 | 2.800972634676e-3 | 约 1 |

|---|---:|---:|

|---|---:|---:|---:|---|
| Neumann | 32 | 1480 | 3.826671130501e-8 | false |
| Neumann | 64 | 0 | 1.341606980750e-13 | false |
| Dirichlet | 32 | 19169 | 3.023655932547e-4 | false |

当前局部投影上限为 20 步，以参数步长 `2e-12` 作为停止阈值。表中 `projection_not_converged` 是评价调用次数，不是独立网格节点数、交点数或失败外迹点数；其判断也不等同于“投影残差超过 2e-12”。代码仍记录并使用可返回的结果，只有非有限/奇异情况抛错。这一限制真实存在，尤其 D/N32，不能用最终 PDE 收敛掩盖。

上述投影残差与 Python 历史对照接近，说明本地复现了该局部评价策略，也同时继承了其局限。`support_paths_certified=false` 则表示默认 trace-first Restrict 没有完整路径分支认证；Spread 的全部网格事件认证成功并不自动替代这项证明。

Neumann 常跳跃探针 `J0=1,J1=0` 的内部指示函数误差为 N32 `2.025934e-15`、N64 `1.582849e-14`；外部值迹误差分别为 `2.109424e-15`、`1.509903e-14`。Dirichlet 对此探针记录 `constant_jump_checked=false`，其数值字段 0 不代表已通过同一种探针。

### 5.3 原先 N64 为什么中止

修复前并不是已找到的 4928 个事件未认证，而是 4 条最终证实无交点的候选边仍被标成 `unresolved`，触发“所有候选边必须具有完整认证根集”的安全守卫。原始诊断保留在 [四条未认证边清单](../tests/cases/trace_first_3d/results/python64_diagnostics_20260909/N64/uncertified_edges.txt) 和 [中止日志](../tests/cases/trace_first_3d/results/python64_diagnostics_20260909/N64_stderr.log)。这些边的诊断 `near_tangent=false`，因此不能把这次失败简单归结为“已经确认的相切交点”。

原控制流在最近点迭代未收敛时直接退出，未继续尝试原本已有的独立分离证书。修复允许无 `box_root` 的盒子在最近点失败后仍尝试带接触容差和 roundoff 保护的正权有理 Bézier 控制凸包分离检查；只有整套检查成立才认证无根，否则仍保持 `unresolved`。它不借助端点标签猜测无根，不删除已找到的根，也未放宽容差或提高全局预算。

默认 `2h` 几何尺度、证书深度 6 下，四条边都已认证为空；各自 `closest_point_failures=1` 仍被保留，未篡改成最近点成功。邻近双根控制边仍保留 `t=0.2802921791890603` 和 `0.70691717680697819` 两个横截根。完整修复后 N64 的 on/off 运行也都通过几何准备。更详细的修复原理见 [实现说明第 5 节](TraceFirst_Implementation_20260909.md#5-whole-line-几何复用与安全回退)。

## 6. 资源复用与 Python 对照

### 6.1 固定算子缓存 A/B

[N32 Python 规则 A/B 记录](../tests/cases/trace_first_3d/results/python32_cache_v2_20260909/summary.json) 中，Neumann 与 Dirichlet 均为 `cache_comparison_checked=true`，按访问构造和复用构造的固定算子最大差异 `cached_reference_max_error=0`。这是本地缓存等价性检查，不是“所有 C++ 与 Python 矩阵逐项相等”的证明。

主力最终运行没有再次执行 A/B：其 `cache_comparison_checked=false`，数值字段 0 只是默认值，不应当作该次重新验证的结果。A/B 在 N32 的额外耗时分别为 N `4.434006 s`、D `17.978583 s`，已包含于那次各 BVP 总时间。

extended adapter 当前为 P2-only 中心也构造 cubic transfer，因此 P3 中心数包含这项工作，不能与 Python 存档中的“实际 Spread P3 中心数”直接比较。缓存保存仿射评价行，在 setup 结束后释放；不是每次 GMRES 重新求中心，也不是把缓存永久保留到所有网格层。
