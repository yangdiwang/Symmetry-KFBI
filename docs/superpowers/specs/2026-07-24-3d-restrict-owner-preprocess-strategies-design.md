# 3D restrict-owner geometry preprocessing strategy design

## Goal

Replace the current use of a full general NURBS segment-intersection query
for every wrong-side tricubic support node with two selectable preprocessing
strategies:

1. a decision-oriented optimized intersection strategy;
2. a geometry-region, certified-closest-point, and optimized-intersection
   hybrid strategy.

Both strategies must operate on the exact queries generated by KFBI trace
template construction. They must be compared against the current full
intersection implementation for owner accuracy, preprocessing cost, and
end-to-end KFBI numerical behavior.

## Scope

This change applies only to crossing-owner selection in
`PanelCenterHarmonicJetKFBI3D::build_trace_sample()`.

It does not replace or weaken:

- `NurbsCartesianDomain3D` construction;
- Cartesian-edge barrier construction;
- grid-node inside/outside and component labels;
- multi-crossing parity used by geometry preprocessing;
- the Cauchy fit, spread, FFT, GMRES, or restrict formulas.

The existing full `NurbsSurfaceIntersector3D::intersect_segment()` route is
retained as the accuracy oracle and final fail-closed fallback. The current
production default remains unchanged until the experiments in this design
have passed.

## Required KFBI information

`GridPair3D::domain_label()` already determines whether a stencil node lies
on the requested side. The remaining geometry question is not a complete
surface-intersection problem. It is:

> Does this wrong-side query-to-support segment require a Cauchy correction
> owner on a foreign non-G1 patch, and if so which surface DOF owns it?

The numerical operator consumes `owner_dof`. Exact reproduction of the
current seven detailed intersection reason codes is not required on a
certified fast path because a no-foreign certificate intentionally does not
solve target/G1 roots. The following are required:

- exact `owner_dof` agreement with the full-intersection oracle;
- exact target-versus-foreign-reroute agreement;
- no false foreign owner and no missed foreign owner;
- a separate query-path diagnostic that does not fabricate an oracle reason.

## Modes

Define:

```cpp
enum class RestrictOwnerPreprocessMode3D {
    FullIntersectionReference,
    OptimizedIntersection,
    RegionClosestHybrid
};
```

`FullIntersectionReference` is an oracle and diagnostic mode.
`OptimizedIntersection` and `RegionClosestHybrid` are the two candidate
production modes requested by this study.

All modes return a common result containing:

```cpp
struct RestrictOwnerPreprocessResult3D {
    int owner_dof;
    RestrictOwnerNormalizedClass3D owner_class;
    RestrictOwnerQueryPath3D query_path;
    std::optional<NurbsSurfaceCrossing3D> foreign_crossing;
};
```

The normalized class distinguishes target, unique foreign, and fail-closed
target fallback. The path records how the result was obtained, including:

- `FullIntersection`;
- `SweepTargetOnly`;
- `SegmentTargetOnly`;
- `ClosestCertifiedMiss`;
- `ClosestCertifiedRoot`;
- `OptimizedIntersection`;
- `FullIntersectionFallback`.

## Owner-compatible topology

For a target DOF, the owner-compatible patch set is exactly the target patch
plus the patch IDs already stored in
`cloud.patches[target_patch].smooth_patch_ids`.

The fast paths must reproduce this current local owner rule. They must not
replace it with the transitive closure of a global G1 component. A distant
patch connected through a chain of G1 joins is not automatically a local
owner-compatible patch.

Periodic and G1 seams are merged only through the existing explicit NURBS
topology. Non-G1 joins are never merged.

## Strategy 1: optimized intersection

### Conservative foreign gate

The rational-Bezier acceleration structure is queried with the segment AABB,
expanded by the existing geometry tolerance. Candidate leaves are partitioned
into owner-compatible and foreign non-G1 leaves.

If no foreign leaf overlaps the conservative segment bounds, the owner is
certified to remain the target. No root solve, root list, canonicalization, or
close-root analysis is performed.

An AABB overlap is only a possible hit. It never certifies an intersection.

### Decision-oriented slow path

When foreign candidates exist:

1. Process foreign candidates first.
2. Reuse the existing Bezier intersection, transversality, feature-contact,
   seam canonicalization, and unresolved-candidate tolerances.
3. Classify only `zero`, `one reliable foreign`, or `multiple/uncertain`.
4. Stop after a second independent crossing has made the current owner a
   target fallback.
5. If no reliable foreign crossing exists, return the target.
6. If exactly one reliable foreign crossing exists, check all remaining
   surface candidates, including compatible leaves, for another crossing or
   unresolved event.
7. Only when every other candidate is certified absent may the unique
   foreign root be mapped through the existing parameter-space 2-by-2 DOF
   selection.

Overlap, endpoint roots, near tangency, feature-edge contact, unrelated
coincidence, unresolved subdivision, and multiple roots remain fail-closed
target fallbacks.

The full intersector remains the fallback when the capped query cannot prove
the same numerical owner decision.

## Strategy 2: region and certified closest-point hybrid

This strategy uses the optimized intersection strategy as its fallback.

### Sample-level region certificate

For one target DOF, side, and normal layer, construct the conservative sweep
AABB of the query point and its complete 4-by-4-by-4 stencil. If every
overlapping Bezier leaf belongs to the owner-compatible set, all wrong-side
nodes in that sample are certified target-owned.

This certificate remains numerically valid even if the compatible surface
contains multiple roots or tangential contacts because every such event
retains the target owner under the current KFBI rule.

### Segment-level region certificate

Samples that fail the sweep certificate are classified per wrong-side
segment. A segment with no foreign candidate is certified target-owned.
Existing projected-control or control-hull separation may reject AABB false
positives. If every foreign leaf is certified separated, the owner remains
the target.

### Closest-point path

The existing
`closest_point_nurbs_bezier_element_to_segment_3d()` implementation is reused.
A triangle or precomputed element sample may provide a preferred parameter
seed.

Closest point is a witness and seed, not by itself a proof of absence or
uniqueness. A result is accepted only when:

- exactly one strictly interior foreign Bezier leaf remains unresolved by
  separation;
- all other surface leaves, including owner-compatible leaves, are certified
  misses;
- the closest-point solve converges;
- its distance satisfies the existing root tolerance;
- the segment parameter is strictly interior;
- the patch and element parameters are strictly interior;
- transversality exceeds the producer's reliable threshold;
- the existing single-root certificate succeeds.

A certified positive-distance miss returns the target. A certified unique
transverse root returns the foreign owner. Every other outcome falls back to
`OptimizedIntersection`.

Roots near an element boundary, patch boundary, G1 or periodic seam, non-G1
feature edge, vertex, endpoint, overlap, or near-tangent configuration are
never accepted by the closest-point fast path.

## Geometry interfaces

Core geometry exposes an opaque candidate facade from
`NurbsSurfaceIntersector3D`; application code must not depend on BVH node
indices or mutable internal vectors. The facade supports:

- conservative segment and sweep candidate collection;
- patch and component metadata for each candidate;
- filtered decision-oriented intersection;
- typed terminal outcomes:
  `CertifiedMiss`, `CertifiedUniqueTransverseRoot`, and `Unresolved`.

The typed closest-point/root certificates are extracted from the existing
Bezier intersection implementation so both the full and fast routes use the
same tolerances.

Application-level ownership is implemented in new focused files:

- `apps/restrict_owner_geometry_preprocessor_3d.hpp`;
- `apps/restrict_owner_geometry_preprocessor_3d.cpp`;
- `apps/restrict_owner_geometry_preprocessor_3d_test.cpp`.

`PanelCenterHarmonicJetKFBI3D` delegates only wrong-side owner queries to this
component. Accumulation order for owner correction polynomials remains
unchanged.

## Diagnostics

Normal production runs use aggregate counters and no per-query clock reads.
Benchmark mode records:

- total wrong-side queries and elapsed preprocessing time;
- queries per second and peak working memory;
- compatible and foreign AABB candidates;
- sweep and segment target certificates;
- control-hull rejections;
- closest-point attempts, convergence, iterations, certified misses, certified
  roots, and unresolved outcomes;
- optimized and full fallback counts by cause;
- normalized target and foreign decisions;
- oracle owner mismatches;
- foreign true positives, false positives, false negatives, and wrong owners;
- maximum mismatched interpolation weight;
- time spent in region queries, closest point, optimized intersection, and
  full fallback.

Only mismatches are written per query. Successful millions-of-row query logs
are not emitted.

## Benchmark protocol

### Shared workload

Each case constructs the real KFBI grid, native NURBS geometry, Cartesian
domain labels, surface DOFs, normal layers, and 4-by-4-by-4 interpolation
stencils. The exact same compact wrong-side query list is replayed for all
three modes.

The full reference is evaluated once for accuracy. Timed candidate runs do
not execute the oracle in their measured region. Policy order is alternated
after one untimed warm-up.

Release x64 builds are used. N=16 and N=32 candidate timings use five
repetitions, N=64 uses three, and the accepted N=128 run uses one. Reports
include median and p95 where repeated samples exist.

### Geometry and pose matrix

Under-resolved stress cases:

- identity torus, hollow cylinder, and L-prism at N=16.

Grid-scaling and rigid-position cases at N=32 and N=64:

- torus: identity and axis-(1,2,3) 17-degree rotation;
- hollow cylinder: identity and the same rotation;
- L-prism: identity, the same rotation, and rotation plus the existing
  `t_xyz_1` translation.

The final expensive case is the rotated L-prism at N=128.

The unit suite additionally contains:

- same-patch and G1 target crossings;
- a unique foreign non-G1 transverse root;
- an AABB false positive with certified miss;
- two roots on one leaf and roots on different leaves;
- near tangency, endpoint contact, overlap, and feature-edge contact;
- element and patch parameter-boundary roots;
- a periodic seam;
- a three-patch G1 chain that must not use transitive owner compatibility;
- a partial one-to-many L-prism connection;
- unrelated coincident patches and multiple components.

### End-to-end KFBI comparison

For N=32 and N=64, every geometry/pose case above runs the existing
Dirichlet crossing-owner manufactured harmonic problem under all modes. The
rotated L-prism also runs at N=128.

Preprocessing time is reported separately from pipeline and solve time.
GMRES time is never included in the owner-preprocessing speedup.

## Accuracy gates

A candidate mode is accepted only if, across the complete oracle workload:

- `owner_mismatch == 0`;
- `foreign_false_positive == 0`;
- `foreign_false_negative == 0`;
- `foreign_wrong_owner == 0`;
- foreign precision and recall both equal one;
- owner correction arrays agree within the existing floating accumulation
  tolerance;
- no geometry query occurs during GMRES;
- GMRES convergence flags and iteration counts match;
- final residuals retain the current bounds;
- interior maximum error, exact-grid error, and exact-equation residual agree
  with the oracle to relative `1e-12`;
- measured convergence orders do not decrease.

The original seven detailed reason-code agreement is reported but is not an
acceptance gate for certified target paths.

A policy that misses an accuracy gate remains available only as an
experimental mode and is not eligible to become the production default.

## Output

Write generated, uncommitted CSV files to a dedicated result directory:

- `preprocess_timing_repeats.csv`;
- `preprocess_summary.csv`;
- `preprocess_accuracy.csv`;
- `preprocess_path_counts.csv`;
- `preprocess_mismatches.csv`;
- `kfbi_numerical_results.csv`.

The final report compares:

- preprocessing seconds and speedup;
- total pipeline seconds and speedup;
- path coverage and fallback rate;
- closest-point and intersection work;
- exact owner accuracy;
- KFBI error, convergence order, GMRES iterations, and residuals.

No benchmark output or run log is committed.

## Expected decision

The study does not preselect a winner. `OptimizedIntersection` provides the
lower-risk control. `RegionClosestHybrid` is selected only if it passes every
accuracy gate and gives a material additional preprocessing speedup on the
curved cylinder and torus as well as the nonconvex L-prism.
